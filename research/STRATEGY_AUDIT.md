## 审计结论

当前正式策略仍是：

```text
120 日长期趋势
  → 绝对 CUSUM 事件
  → 10% / 14% ATR 风险预算
  → 10 ATR 止盈、6 ATR 止损
  → 固定四特征 walk-forward HMM 退出
  → t+1 开盘严格执行
```

策略只做多或空仓，不做空、不借钱，最高 100% 黄金名义敞口。清理前后的正式回测结果完全一致：

| 毛收益 | 198.65% | 198.65% |

因此本轮属于实现清理、发布安全修复和网站增强，不是策略参数优化，也没有利用开发历史重新选参。

## 发布安全问题与修复

### 1. TLS 校验曾被关闭

`requests verify=False`、curl `-k` 以及全局 warning 屏蔽会允许无法验证的行情进入网站。现已恢复系统 CA 证书验证并保留运行警告。

### 2. 错资产回退

COMEX 主行情与缓存均失败时，旧代码可能改用上金所 Au99.99。两者币种、价格单位和交易时段不同，会污染信号和回测。该回退已删除；现在只接受 `101.QO00Y` 或同一 COMEX 黄金序列的缓存/GC 延伸，否则发布失败。

质量报告新增 `assetIdentity`，网站检查要求其通过。

### 3. 公开 JSON 非原子写入

异常中断可能留下半写 JSON。四个公开文件现通过临时文件序列化成功后再原子替换。

### 4. 配置指纹没有覆盖实现

旧前瞻指纹只包含版本号和配置；如果忘记提升版本，函数逻辑变化可能不被发现。新指纹额外包含正式特征、HMM、信号和严格执行函数的源码 SHA-256。

当前前瞻账本仍为 0 天，因此允许一次空账本指纹迁移；一旦已有记录，指纹变化仍会强制声明新版本。

### 5. 日常发布缺少安全入口

新增 `scripts/update_website_daily.sh`：

- 只允许干净的 `main`。
- 使用 Git 目录锁防止重复执行。
- 更新前后核对远端。
- 默认避免北京时间过早发布未完成 COMEX 日线。
- 运行数据更新和完整 `npm run verify`。
- 只允许四个公开 JSON 被自动提交。
- 无有效变化时不创建空提交。
- 禁止 force push；远端在运行期间变化时停止。

## 仍需明确的限制

1. 当前主标的是连续黄金价格 proxy，不是逐合约 GC/MGC 交易账本；未包含真实换月价差、整数合约和保证金规则。
2. 2023-02-28 之后已被反复研究，只能视为开发历史。真正前瞻记录从 2026-07-13 开始，目前为 0 天。
3. 原始行情缓存位于被忽略的 `data/raw/`，新机器不能仅凭 Git 仓库逐字节复现历史供应商数据。
4. Python 依赖仍是版本下限而非带哈希锁文件；升级依赖前必须重新运行全量回测。
5. 仓库内没有 GitHub Actions 或 Vercel 部署状态核验；脚本能确认 GitHub 推送，不能确认托管平台最终部署成功。
6. 每日自动更新最好在专用 clone/worktree 中运行；目录锁不能阻止不遵守同一锁的其他程序修改工作区。
